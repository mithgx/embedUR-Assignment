# Troubleshooting Inter-VLAN Communication

VLANs are designed to isolate traffic from each other, so devices in VLAN 10 and VLAN 20 not being able to communicate is actually expected behavior by default. They exist on separate broadcast domains and behave as two completely different networks. The missing piece is a Layer 3 device to route traffic between them.

The most common fix is the Router-on-a-Stick method, where a router is connected to the switch via a trunk port. The router is configured with subinterfaces — one for each VLAN — and each subinterface acts as the default gateway for its respective VLAN. Without this, there is simply no path for traffic to travel from one VLAN to the other.

Even with a router in place, the PCs must have the correct default gateway configured. Devices in VLAN 10 should point to the VLAN 10 subinterface IP, and devices in VLAN 20 should point to the VLAN 20 subinterface IP. If the gateway is wrong or missing on any PC, that device's traffic will never reach the router and inter-VLAN communication will still fail.

On the switch side, the port connecting to the router must be set as a trunk port carrying both VLANs. If it is left as an access port, only one VLAN's traffic will reach the router and the other will be completely blocked. Running `show interfaces trunk` on the switch confirms whether the trunk is properly configured and which VLANs are being carried.

Finally, on the router, the parent physical interface must be brought up with `no shutdown` before any subinterfaces can become active. This is the most commonly missed step — the subinterfaces will show as down if the parent interface is administratively disabled, even if the subinterface configuration is perfectly correct.
