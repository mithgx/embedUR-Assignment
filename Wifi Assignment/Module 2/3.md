# CAPWAP in OSI Model and Tunnels

CAPWAP operates at the Application Layer (Layer 7) of the OSI model, while relying on UDP at the Transport Layer. It uses:

* UDP port 5246 → Control traffic
* UDP port 5247 → Data traffic

CAPWAP establishes two logical tunnels between the AP and controller:

1. Control Tunnel
   This tunnel carries management and control information such as AP registration, configuration updates, keepalive messages, and event notifications. It is secured using DTLS to ensure confidentiality and integrity.

2. Data Tunnel
   This tunnel carries actual client data traffic (user packets). Depending on deployment mode:

   * Centralized forwarding → traffic goes through controller
   * Local switching → traffic is bridged locally at AP

Key purpose of these tunnels:

* Separate control and data planes
* Enable centralized network control
* Provide secure communication (via DTLS)
* Support scalable multi-AP deployments

This separation is critical for efficient enterprise Wi-Fi design and aligns with control/data plane architecture principles.
