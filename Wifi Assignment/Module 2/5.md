# CAPWAP Tunnel Maintenance

CAPWAP tunnels between the Access Point (AP) and Wireless LAN Controller (WLC) are maintained using a combination of keepalive mechanisms, session management, and secure encapsulation.

After initial setup (discovery, join, DTLS establishment), the AP and controller maintain the tunnel through:

* Keepalive Messages
  Periodic heartbeat messages are exchanged over the control tunnel to verify connectivity. If keepalives fail, the AP assumes the controller is unreachable.

* DTLS Session Maintenance
  The control tunnel is secured using DTLS, which maintains session state, encryption keys, and integrity checks.

* Echo Requests/Responses
  CAPWAP-specific echo messages help detect link failures and latency issues.

* Retransmission and Timers
  Timers are used to detect packet loss or inactivity. If thresholds are exceeded, the AP may attempt to reconnect or failover to another controller.

If the tunnel drops:

* AP enters discovery state again
* Attempts to rejoin same or backup controller
* May switch to fallback mode (e.g., standalone/local switching in some deployments)

This mechanism ensures reliability and continuous connectivity in enterprise Wi-Fi networks.
